# Femme Digital CMS – מערכת עריכה ללקוחות

מערכת שמאפשרת ללקוחות של הסוכנות לערוך את האתר שלהם – **טקסטים, תמונות, קישורים, צבעים ופונטים (כל פונט מ-Google Fonts)** –
בכניסה עם **שם משתמש וסיסמה**, בעיצוב של Femme Digital, **בלי לגעת בקוד ובלי יכולת לשבור את המבנה**.

האתרים עצמם נשארים ב-**GitHub Pages** (חינם), עם דומיין של הלקוח. המערכת היא שירות אחד קטן ב-Cloudflare (חינם) שמשרת את כל הלקוחות.

## איך זה עובד

```
לקוח ──סיסמה──► Cloudflare Worker (מסך הניהול + API)
                    │  מחזיק את הטוקן של GitHub (הלקוח לא רואה אותו)
                    │  בודק כל שדה מול רשימה מותרת
                    ▼
        ריפו של האתר ב-GitHub:  cms/edits.json  +  cms/uploads/…   ← זה כל מה שהלקוח יכול לשנות
                    │  GitHub Pages מפרסם
                    ▼
        האתר המפורסם  +  cms/cms-kit.js  ← סקריפט קטן שמחיל את העריכות מעל העמוד המקורי
```

* **הקוד של האתר לא משתנה.** העריכות נשמרות בקובץ נפרד (`cms/edits.json`) ומוחלות מעל העמוד בזמן טעינה.
  כל עריכה מזוהה לפי מיקום האלמנט בעמוד, ולכן אפשר לשנות **תוכן** בלבד – לא להוסיף, למחוק או להזיז אלמנטים.
* **עריכה ויזואלית.** האתר נפתח בתוך מסך העריכה; לחיצה על כל טקסט / תמונה / כפתור פותחת אותו לעריכה,
  ולחיצה כפולה על טקסט מאפשרת להקליד ישירות על הדף. יש תצוגת מחשב/טאבלט/נייד, ביטול ושחזור, היסטוריית גרסאות.
* **עיצוב טקסט** – גודל (מתכווץ אוטומטית בנייד), מודגש, נטוי, קו תחתון, קו חוצה ויישור, לכל טקסט.
* **מבנה** – שכפול של כל אלמנט או קטע שלם, הזזה למעלה/למטה, הסתרה, והוספת טקסט חדש (עותק של טקסט קיים). בלשונית **מבנה** רואים את כל קטעי הדף וסוגרים עליהם בלחיצה.
  המבנה נשמר כרשימת פעולות (שכפל / הזז / הסתר) ולא משנה את קוד האתר; כל פעולה ניתנת לביטול. כל אלמנט מקבל "תווית" עם מיקומו המקורי בעמוד,
  ולכן עריכות נשארות צמודות לאלמנט הנכון גם אחרי הזזה, ולעותק יש עריכות עצמאיות משלו.
* **הוספת אלמנטים** – תמונה (העלאה), כפתור, סרטון (קישור YouTube/Vimeo בלבד, מוטמע בפרטיות), קובץ להורדה (PDF, Word, Excel, PowerPoint, ZIP עד 10MB), טקסט, כותרת ומפריד.
  האלמנט נבנה מתבנית קבועה ולוקח את העיצוב של האתר (כפתור חדש מקבל את המחלקות של כפתור קיים, וכו'). אי אפשר להוסיף HTML או קוד חופשי;
  השרת מאשר רק את הסוגים האלה, מאמת קישורי וידאו מול רשימה סגורה, ובודק את תוכן הקבצים שמועלים (ולא רק את הסיומת).
* **צבעים** – המערכת סורקת את הצבעים שבשימוש באתר, ושינוי של צבע מחליף אותו בכל האתר בבת אחת (גם משתני CSS).
* **פונטים** – פונט לכותרות, פונט לטקסט, ופונט לכל אלמנט. אפשר לבחור מרשימה או להקליד כל שם מ-Google Fonts;
  המערכת בודקת שהפונט קיים ואם הוא תומך בעברית.
* **אבטחה** – הלקוח לעולם לא מקבל גישה ל-GitHub. השרת כותב רק ל-`cms/edits.json` ול-`cms/uploads/*`, בונה מחדש כל עריכה
  מרשימה מותרת (חוסם `javascript:`, צבעים/סלקטורים/פונטים לא תקינים, קבצי תמונה מזויפים ועוד), ומתעד בכל commit מי ערך.

## הקמה חד-פעמית (כ-20 דקות)

צריך: חשבון [Cloudflare](https://dash.cloudflare.com/sign-up) חינמי, וחשבון GitHub שמחזיק את ריפואי האתרים.

1. **טוקן ל-GitHub** – https://github.com/settings/personal-access-tokens/new  
   *Repository access* ← הריפואים של האתרים (אפשר להוסיף בהמשך) · *Permissions* ← **Contents: Read and write**.
   שמרו את הטוקן (`github_pat_…`) – הוא יישב רק ב-Cloudflare.
2. **KV** – ב-Cloudflare: *Workers & Pages ← KV ← Create namespace* (שם: `femme-cms`) והעתיקו את ה-ID ל-`worker/wrangler.toml`
   במקום `REPLACE_WITH_KV_NAMESPACE_ID`.
3. **פריסה אוטומטית** – בריפו הזה (`webadmin`): *Settings ← Secrets and variables ← Actions ← New repository secret*:

   | Secret | ערך |
   |---|---|
   | `CLOUDFLARE_API_TOKEN` | טוקן Cloudflare עם תבנית *Edit Cloudflare Workers* |
   | `CLOUDFLARE_ACCOUNT_ID` | מזהה החשבון (מופיע בדף Workers) |
   | `CMS_ADMIN_PASSWORD` | הסיסמה שלכן (בעלת הסוכנות) – משתמש `admin` |
   | `CMS_SESSION_SECRET` | מחרוזת אקראית ארוכה (למשל `openssl rand -hex 32`) |
   | `CMS_GITHUB_TOKEN` | הטוקן מסעיף 1 |

   אחרי מיזוג ל-`main` ה-workflow *Deploy CMS to Cloudflare* יעלה את המערכת לכתובת `femme-cms.<חשבון>.workers.dev`.
   (אפשר גם ידנית: `cd worker && npx wrangler deploy`, ו-`npx wrangler secret put …` לכל סוד.)
4. **כתובת במותג** – ב-Cloudflare: Worker ← *Settings ← Domains & Routes ← Add custom domain* ← `cms.femme-digital.com`
   (הדומיין צריך להיות מנוהל ב-Cloudflare; אם לא – אפשר להשאיר את כתובת ה-workers.dev).

## חיבור אתר חדש ולקוח חדש

1. האתר מתפרסם ב-GitHub Pages כרגיל (עם דומיין הלקוח ב-*Settings ← Pages ← Custom domain*).
   ודאו ש**תיקיית `cms/` מתפרסמת** עם האתר (בפריסה מ-branch או מכל הריפו זה אוטומטי).
2. היכנסו למסך הניהול כ-`admin` ← **אתרים ← הוספת אתר**: שם, מזהה, `owner/repo`, כתובת האתר המפורסם, עמודים (`index.html, about.html…`).
3. לחצו **חיבור לעריכה** (פעם אחת): המערכת מוסיפה לריפו את `cms/cms-kit.js`, קובץ `cms/edits.json` ריק,
   ותג `<script>` אחד לכל עמוד. זה השינוי היחיד בקוד האתר.
4. **לקוחות ← לקוח חדש**: שם, שם משתמש, סיסמה (נוצרת אוטומטית), ובחירת האתרים. תקבלו הודעה מוכנה לשליחה בוואטסאפ עם פרטי הכניסה.

מחיקת לקוח חוסמת אותו מיד. הסרת האתר מהמערכת לא מוחקת את האתר עצמו.

## מגבלות ודברים טובים לדעת

* **אתרים שנבנים בג'אווסקריפט** (כמו אתר Alternative, שמשמש גם כאתר הדוגמה בבדיקות) נתמכים – העריכות מוחלות גם על תוכן שנוצר אחרי הטעינה.
* **מבנה שישתנה אחרי שהלקוח כבר ערך** (הוספת/הזזת אלמנטים) עלול להזיז עריכות קיימות, כי הן מזוהות לפי מיקום.
  אחרי שינוי מבנה גדול כדאי לבדוק את האתר במסך העריכה. אפשר לקבע אלמנט חשוב עם `id` ייחודי – עריכות יזוהו לפיו.
* **עיכוב קל בטעינה:** העמוד מוסתר עד שהעריכות הוחלו (עד ~1.5 שנ', בדרך כלל מאות מילישניות) כדי שלא יהבהב התוכן המקורי.
  למנועי חיפוש שמריצים JavaScript (גוגל) התוכן הערוך נראה כרגיל.
* **פונטים** נטענים מ-Google Fonts (שרתים של גוגל). אם רוצים אירוח עצמי, אפשר להטמיע פונט בקוד האתר במקום.
* **הטוקן של GitHub** נותן כתיבה לריפואים שבחרתן – אבל הוא יושב רק בשרת, והשרת כותב רק לשני נתיבים. לפרויקטים גדולים
  מומלץ בהמשך לעבור ל-GitHub App (גם הוא נתמך באותו מבנה).
* **Cloudflare חינם**: מספיק לעשרות לקוחות. הכניסה מוגבלת ל-10 ניסיונות כושלים ל-15 דקות לכל כתובת IP.

## פיתוח ובדיקות

```bash
node --test tests/worker.test.mjs          # בדיקות שרת: הרשאות, ולידציה, חיבור אתר (76)
NODE_PATH=$(npm root -g) node tests/kit.mjs # בדיקות ערכת העריכה בדפדפן, בשני origins (25)
NODE_PATH=$(npm root -g) node tests/layout.mjs # עיצוב טקסט ופעולות מבנה: שכפול, הזזה, הסתרה, עותקים באתרי scroll-reveal (36)
NODE_PATH=$(npm root -g) node tests/e2e.mjs # תרחיש מלא: חיבור אתר, יצירת לקוח, עריכה, פרסום (דורש playwright)
```

מבנה התיקייה:

```
femme-cms/
  app/            מסך הניהול (סטטי) + brand/ (לוגו ודודלים) + kit/cms-kit.js (נעתק לכל אתר ע"י "חיבור לעריכה")
  worker/         שרת: אימות, משתמשים ואתרים (KV), ממשק מול GitHub, ולידציה
  tests/          בדיקות
```

עדכון ערכת העריכה באתרים קיימים: שנו את `app/kit/cms-kit.js`, פרסו, ולחצו **חיבור לעריכה** באתר (פעולה בטוחה לחזרה).
כשיש גרסה חדשה, העורך מזהה אתר עם ערכה ישנה ומציג הודעה עם כפתור **עדכון עכשיו** (לבעלת הסוכנות); עד העדכון, אפשרויות העיצוב והמבנה מוצגות כבלתי זמינות.

## חיבור דומיין לאתר

באדמין: **אתרים → דומיין** על האתר הרצוי.
1. מזינים את הדומיין שהלקוח רכש (`client.co.il` או `www.client.co.il`).
2. המערכת מציגה את רשומות ה-DNS להגדרה אצל הרשם (דומיין ראשי: 4 רשומות A של GitHub + CNAME ל-`www`; תת-דומיין: CNAME ל-`<owner>.github.io`).
3. לוחצים **בדיקה**. רק כש-ה-DNS תקין המערכת מגדירה את הדומיין ב-GitHub Pages, ממתינה לתעודת HTTPS, מפעילה אכיפת HTTPS ומעדכנת את כתובת האתר.

נדרש: ל-`CMS_GITHUB_TOKEN` (Fine-grained) הרשאת **Pages: Read and write** בנוסף ל-Contents. הערה: תנאי השימוש של GitHub Pages לא מיועדים לאירוח בתשלום; ללקוחות משלמים מומלץ Cloudflare Pages.

## אחסון בתשלום: העברה ל-Cloudflare Pages

באשף הדומיין, אחרי שהוגדר דומיין לאתר: **העברה ל-Cloudflare**. המערכת יוצרת פרויקט Cloudflare Pages מחובר לאותו ריפו, מחכה לבנייה הראשונה, מוסיפה את הדומיין ומציגה את רשומת ה-CNAME החדשה. רק כש-Cloudflare מאשר שהדומיין פעיל היא משחררת אותו מ-GitHub Pages (כך אין downtime). **החזרה ל-GitHub Pages** הופכת את הכל.

הגדרה חד-פעמית:
1. לטוקן ה-Cloudflare (`CLOUDFLARE_API_TOKEN`) מוסיפים הרשאה **Account → Cloudflare Pages → Edit**.
2. ב-Cloudflare: Workers & Pages → Create → Pages → Connect to Git, ולהתקין את אפליקציית **Cloudflare Pages** ב-GitHub עם גישה לריפואים של הלקוחות (פעם אחת; אין צורך להשלים יצירת פרויקט).
3. מריצים את ה-workflow מחדש – הטוקן וה-Account ID מועברים אוטומטית ל-Worker.

## הגדרת DNS אוטומטית (Cloudflare)

כשהדומיין של הלקוח נמצא בחשבון ה-Cloudflare שלכם, בפאנל הדומיין יש כפתור **הגדרת DNS אוטומטית**: המערכת מוצאת את ה-Zone ויוצרת את הרשומות (GitHub Pages, או `<project>.pages.dev` אחרי ההעברה ל-Cloudflare). רשומות A/AAAA/CNAME מתנגשות באותו שם מוחלפות; MX/TXT ואחרות לא נוגעים בהן. לטוקן נדרשות ההרשאות **Zone ← Zone: Read** ו-**Zone ← DNS: Edit** (בנוסף ל-Pages: Edit).

## שכפול עמודים ועמודי תקנון (טקסט בלבד)

- **עמוד חדש:** בעורך, בשורת העמודים: **＋ עמוד חדש (שכפול)** – שם לעמוד + מאיזה עמוד לשכפל. נוצר קובץ HTML חדש באתר (באותה תיקייה, שם קובץ בטוח) והעריכות של המקור מועתקות אליו. עד **10** עמודים משוכפלים לכל אתר. אפשר למחוק רק עמוד שנוצר בשכפול ("מחיקת העמוד"); עמודים מקוריים לא נמחקים.
  העמוד החדש מתפרסם ב-GitHub Pages תוך כדקה, והעורך פותח אותו אוטומטית. כדי שיופיע בתפריט האתר: משכפלים פריט בתפריט ומשנים את הקישור.
- **טקסט בלבד:** באדמין, בעריכת האתר, בשדה "עמודי תקנון – עריכת טקסט בלבד" רושמים את העמודים (למשל `terms.html`). הלקוח יכול בהם לשנות רק טקסט; צבעים, פונטים, מבנה, תמונות, קישורים והוספת אלמנטים חסומים (גם בשרת, לא רק בממשק). עותקים של עמוד נעול נעולים גם הם. בעלת הסוכנות עדיין יכולה לערוך הכול.
- אחרי עדכון הערכה (חיבור לעריכה) גם העותקים מקבלים את הגרסה החדשה.

## קופסאות וצורות לתמונות

- **קופסה:** בבלוק "הוספת אלמנט" – אריח **קופסה**. נוצרת קופסת תוכן עם כותרת וטקסט, בעיצוב של כרטיס קיים באתר (למשל כרטיסי מחיר) – ואם אין כזה, בעיצוב נקי. אפשר לערוך את הטקסטים בתוכה, ולקבוע **רדיוס פינות, עובי וצבע מסגרת, וצל** (גם לקופסאות קיימות: בוחרים אותן ב"בחירת האלמנט שמעל").
- **תמונות:** בבחירת תמונה – **צורה וחיתוך**: עיגול, ריבוע מעוגל, קשת, בועה, משולש, מעוין, מחומש, משושה וכוכב; יחס חיתוך (1:1, 4:3, 3:4, 16:9, 9:16) ובחירת החלק שנשאר בפריים. התמונה נחתכת ולא נמתחת.
- דורש ערכת עריכה בגרסה 5: באתרים שחוברו קודם יש ללחוץ פעם אחת "חיבור לעריכה".

## עמודות, מרווחים וגודל

- **חלוקה לעמודות:** בבלוק "הוספת אלמנט" – **2 עמודות** / **3 עמודות** יוצרים שורה של קופסאות זו לצד זו (במסך צר הן יורדות לעמודה אחת).
- **קופסאות שכבר באתר** (למשל כרטיסי מחיר שנוגעים זה בזה): סמנו קופסה ← "בחירת האלמנט שמעל" עד שכל השורה מסומנת ← **גודל, מרווחים ועמודות**: מספר עמודות (1–4) ו**מרווח בין הפריטים**.
- לכל קופסה/תמונה: **רוחב** (באחוזים), **גובה מינימלי**, **ריפוד פנימי** ו**מרווח מתחת**.
- דורש ערכת עריכה בגרסה 6 (לחיצה אחת על "חיבור לעריכה" באתרים קיימים).


## עמוד רכישת דומיין (`domains.html`)

עמוד ציבורי שבו מבקרים בודקים אם שם פנוי ובכמה, ומזמינים דרך וואטסאפ. הבדיקה רצה ב-Worker מול **Cloudflare Registrar API** (בטא): `POST /api/public/domains/check` (בלי התחברות, עד 30 בדיקות בדקה לכל מבקר). הבדיקה לא קונה כלום ולא מזיזה כסף.

- דרוש: `CF_API_TOKEN` עם הרשאת **Account ← Registrar** (בנוסף להרשאות הקיימות) ו-`CF_ACCOUNT_ID`. בלי ההרשאה העמוד מציג "בדיקת דומיינים לא זמינה כרגע".
- הסיומות הנבדקות (`TLDS` ב-`worker/src/domains.js`): com, net, org, app, dev, xyz, info, online, site, shop, cloud, pro. `.co.il` אינו נתמך אצל Cloudflare, ולכן העמוד מפנה לוואטסאפ.
- המחיר המוצג: מחיר Cloudflare בדולרים × `USD_ILS` + `SERVICE_FEE_ILS` (שני קבועים בראש הסקריפט ב-`domains.html`), מעוגל כלפי מעלה.
- **הזמנה (חצי-אוטומטי):** הלקוח משאיר שם וטלפון, ו-`POST /api/public/domains/order` שומר הזמנה (אחרי בדיקה חוזרת של הזמינות והמחיר) ומחזיר מספר הזמנה, וכפתור וואטסאפ אליכן. בניהול, בלשונית **הזמנות דומיינים**: שולחות ללקוח קישור תשלום, לוחצות **סימון כשולם**, ואז **רישום ב-Cloudflare**. הרישום בודק שוב זמינות ומחיר (אם המחיר עלה ביותר מ-10% מבקש אישור), קורא ל-`POST /registrar/registrations` ורושם את הדומיין בחשבון Cloudflare שלכן, בכרטיס שמוגדר שם. אם הרישום נכשל ההזמנה נשארת "שולמה" עם הסיבה, ואפשר לנסות שוב, לסמן "נרשם ידנית" או לבטל. אין חיבור לסאמיט: התשלום והסימון נעשים ידנית.
- שער הדולר והעמלה נקבעים בשרת: משתני סביבה `DOMAIN_USD_ILS` (ברירת מחדל 3.7) ו-`DOMAIN_FEE_ILS` (ברירת מחדל 0). הקבועים בדף משמשים רק כגיבוי.

## צ'אט עריכה, קטעים אופציונליים וקטעים שנוצרים בצ'אט

**צ'אט עריכה.** לשונית "צ'אט" בעורך: הלקוחה כותבת בעברית ("הגדילי את הכותרת"), Claude מחזיר פעולות והעורך מבצע אותן בתצוגה החיה. הכול ניתן לביטול ועולה לאתר רק אחרי "פרסום באתר".
- הקמה: סוד `ANTHROPIC_API_KEY` ב-GitHub (Settings → Secrets) והרצה ידנית של `deploy-cms.yml` (הוא לא רץ אוטומטית על שינוי סוד).
- הפעלה פר-אתר: תיבת "צ'אט עריכה פעיל באתר הזה" בטופס האתר (הבעלים תמיד רואה את הצ'אט).
- אופציונלי: `CHAT_MODEL` (ברירת מחדל `claude-sonnet-5-5`), `CHAT_DAILY_LIMIT` (30 הודעות ליום ללקוח, הבעלים ללא הגבלה), `AGENCY_WHATSAPP`.
- בעמודי "טקסט בלבד" הצ'אט משנה טקסטים בלבד.
- אתרים מחוברים צריכים גרסת ערכה 9: "חיבור לעריכה" מחדש.

**קטעים אופציונליים.** מסמנים בקוד האתר `data-cms-optional="המלצות"` (אפשר גם `hidden`). הקטע מוסתר עד שהלקוחה מפעילה אותו בעורך או בצ'אט.

**קטעים שנוצרים בצ'אט.** Claude כותב HTML בסגנון האתר; השרת והערכה מנקים אותו (תגיות, מאפיינים וסגנונות מורשים בלבד, בלי תמונות/סקריפטים). טקסט מחליף מסומן `data-cms-todo`, והעורך מזהיר לפני פרסום אם נשאר כזה.
